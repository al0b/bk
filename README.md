# Пляжной волейбол — турниры

Веб-приложение для проведения серии турниров по пляжному волейболу:
10 игроков, 2 площадки, 2 круга, формат 2×2 (на площадке 5 человек, один отдыхает в каждой игре).
Турниры проходят по средам; состав нового турнира предзаполняется из итога прошлого.

## Как запустить

Откройте `index.html` в браузере (двойной клик или перетаскиванием в окно).
Сборки и зависимостей нет — всё в одном файле. Состояние хранится в `localStorage`,
после перезагрузки продолжится с того же места.

## Комнаты

Приложение поддерживает **несколько комнат** — независимых цепочек турниров, каждая со своей
историей и своей (опциональной) синхронизацией. В БД комната хранится по **GUID** (названия могут
повторяться — пользовательское название только для интерфейса).

- Вкладка **«Комнаты»** (в шапке): список комнат (название + 🔴 локально / 🟢 синхр. + сколько в
  истории). Кнопки: «Войти» (открывает грядущий турнир), «✕ удалить», «Создать комнату».
- Комната создаётся **без синхронизации**. Синхронизацию можно **добавить позже** — по коду на
  экране «Синхронизация».
- **Синхронизация у каждой комнаты своя** (свой GUID/путь Firebase) — данные одной комнаты не
  влияют на другую. При переключении активной комнаты синхронизация переподключается.
- Открытие ссылки с кодом (`?join=…`) второй раз не создаёт дубль — комната с тем же GUID уже есть.

## Админ (конфиги Firebase)

Вкладка **«Админ»** — управление конфигами Firebase и комнатами в них:

- **Добавить конфиг** (имя + вставка `firebaseConfig`). На экране админа видны только конфиги,
  добавленные **локально** вами. Если вы подключились к турниру по коду — конфиг создаётся
  автоматически, но **скрыт** в админке (он не ваш для управления).
- **Выбрать конфиг** → live-запрос к Firebase (`rooms/`): список комнат (название, завершённых,
  последний турнир, матчей в нём, когда изменено) + кнопка «код».
- **Добавить комнату** в конфиг → GUID + placeholder в Firebase + код/ссылка синхронизации.

## Даты

Среда больше не ориентир. Дата следующего турнира: последний завершённый + 7 дней; если
завершённых нет — сегодня.

## Поток

1. **Грядущий турнир** (экран по умолчанию) — название (по умолчанию дата ближайшей среды
   по Москве) и 10 участников. Если есть завершённые турниры — состав предзаполнен по их
   итогу: порядок по занятым местам (1-3 пл.1, 1-2 пл.2, 4-5 пл.1, 3-5 пл.2), первые 5 —
   новая площадка 1, последние 5 — новая площадка 2 (топ-2 второй и худшие-2 первой
   поменялись местами). Имена и название редактируются. Кнопка «Начать турнир».
2. **Первый круг** — на каждой площадке 5 игр (каждый проводит 4, отдыхает 1). Расписание
   балансное: каждая пара играет в одной команде ровно один раз, в соперниках — дважды.
   Вводите счёт; таблица обновляется. Худшие 2 площадки 1 и лучшие 2 площадки 2 подсвечены.
3. **Переход** — после первого круга лучшие 2 площадки 2 переходят на 1, худшие 2 площадки 1 —
   на 2. Расписание второго круга оптимизируется так, чтобы минимизировать максимальную серию
   подряд идущих игр с учётом серий на конце первого круга.
4. **Второй круг** — аналогично первому, на новых составах. Раскрывающимся блоком
   «Результаты первого круга» можно посмотреть итоги первого, не выходя из второго.
5. **Финал** — результаты **обоих кругов** (игры + таблицы по площадкам). Кнопки:
   «Поделиться результатами» (PNG), «⬇ Экспорт в файл» (JSON), «Начать заново», «Новый турнир →»
   (архивирует текущий и создаёт следующий — следующая среда после текущего, состав из только
   что завершённого).
6. **История** — список завершённых турниров; можно открыть любой и посмотреть полные
   результаты **обоих кругов** (игры со счётом и таблицы по площадкам, только чтение).
   У каждой записи кнопка ✕ (удалить). На экране истории — «⬆ Импорт из файла» (JSON),
   в просмотре турнира — «⬇ Экспорт в файл».

## Детали

- **Даты**: среда по Москве (`Europe/Moscow` через `Intl`). Новый «грядущий» турнир —
  следующая среда **после последнего турнира** (еженедельная каденция, +7 дней от него);
  если турниров ещё нет — ближайшая среда от сегодняшней даты.
- **Дубликаты имён**: при совпадении второму и далее автоматически добавляется индекс
  («Иван», «Иван 2», «Иван 3»).
- **Правило «не больше 5 игр подряд»**: серия считается через границу кругов без перерыва.
  Гарантировать ≤5 во всех случаях нельзя (на каждой площадке обязаны быть игроки с серией
  4 и 3 в конце первого круга; при неблагоприятном переходе минимум достигает 6). Алгоритм
  минимизирует максимальную серию: типично ≤5, худший случай — 6 (~8–10% исходов).
  Серия каждого игрока видна в таблице; при >5 — предупреждение.
- **Поделиться PNG**: две итоговые таблицы рисуются на `<canvas>` (без внешних зависимостей),
   затем `navigator.share` с файлом (мобильные) или скачивание файла (десктоп).

## Синхронизация между устройствами (Firebase Realtime DB)

По умолчанию приложение работает локально (`localStorage`). Чтобы вводить результаты с
нескольких устройств в реальном времени, подключите Firebase Realtime Database (бесплатно).

### Настройка Firebase (один раз, только для ведущего)
1. Зарегистрируйтесь на [console.firebase.google.com](https://console.firebase.google.com),
   создайте проект.
2. **Build → Realtime Database → Create** (режим Test — открыто на 30 дней, либо задайте
   правила вручную). Для быстрого старта правила:
   ```json
   { ".read": true, ".write": true }
   ```
   (открыто — используйте Firebase Auth, если нужна приватность).
3. **Project settings (⚙) → Your apps → Web (`</>`) → Register app**. Скопируйте объект
   `firebaseConfig` (с `apiKey`, `databaseURL`, `projectId`, `appId`).

### Создать код синхронизации (админ)
На экране **«Админ»** → выбрать конфиг → **Добавить комнату** (название) → будет создана комната
в Firebase (GUID) и показан **код/ссылка** вида `…?join=<код>`. Код также можно скопировать из
списка комнат в конфиге.

### Подключить комнату по коду (участник)
На экране **«Синхронизация»** активной комнаты (если она ещё не связана) вставьте код →
**Подключить**. Конфиг Firebase вводить не нужно — он зашит в коде (XOR+base64url). Можно просто
открыть ссылку `?join=<код>` — комната подключится автоматически (дубль по тому же GUID не создаётся).

### Конфликт при связывании
Если локальная комната уже содержит данные и вы подключаете её к непустой удалённой комнате с
другим timestamp — появится экран **«Конфликт данных»**: сравнение (завершённых турниров, последний
турнир + матчей в нём, когда изменено) и где свежее / где больше. Три кнопки:
**Выбрать сервер** (взять удалённые данные), **Выбрать локально** (перезаписать удалённые локальными),
**Отменить** (не связывать). Конфликт только при связывании; после — обычный last-write-wins.

### Как это работает
- Данные подключения (конфиг Firebase + roomGuid) упаковываются в код (XOR + base64url) и
  вкладываются в ссылку `?join=<код>`. Участник декодирует её и подключается без ручного ввода конфига.
- **Синхронизация per-room по GUID**: данные каждой комнаты (`tournaments`, `activeId`, `ts`,
  `name`) лежат в Firebase по пути `rooms/<roomGuid>`. Разные комнаты → разные пути → изоляция. При
  переключении активной комнаты синхронизация переподключается к её пути. Гость не видит
  конфиг (поле пустое); если хочет создать свою синхр. комнату — вводит свой конфиг.
- Листенер Firebase применяет чужие изменения, свои «эхо» подавляются (по nonce).
- Статический `index.html` остаётся на GitHub Pages — добавился только вызов Firebase SDK.
  Без подключения — обычный локальный режим (`localStorage`).
- **Ограничение**: одновременный ввод на двух устройствах в одну секунду может затереть
  правки одного из них (last-write-wins). На практике (люди вводят секунды спустя) надёжно;
  один ведущий — идеально.

## Проверка инвариантов

В консоли браузера:

```js
__test()      // инварианты расписания активного турнира
```

Проверит, что у каждого 4 игры, каждый отдыхает один раз, каждая пара — однократно в одной
команде, и выведет максимальные серии по площадкам.
